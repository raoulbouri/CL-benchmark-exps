- **2026-10-01: Resume semantics.** The DMPEL codebase has no task-level resume: its expert library, router state and replay stores live in process memory between tasks. The harness therefore resumes at the *run* level. A queue skips runs whose result is `complete` and restarts incomplete runs from task 0 as a new attempt (new W&B run id, `-a{n}` suffix in the local output directory). Results are written after every task, so a crash loses at most the task in progress. This replaces the PI_REVIEW Phase 0 gate wording "resumes from its last task".

- **2026-10-01: Finding, not changed: DMPEL-codebase ER clips gradients before unscaling.**

  - **Corrections to the pasted plan.** The files hold `topk_idx`/`topk_coeff` (the router's selected experts and weights per step and env) and, on Long only, `act_grip`; there are no `coefficients`/`gripper` keys or `task_train=` filenames.   - **Logging bug found and fixed (patch v4).** The router hook stayed active after evaluation, so the post-training buffer pass (32-row batches) was logged into the first matrix file of each stage with a stale (loop, step). Rollout calls are always 5 rows with consecutive steps; the analysis filters on that (episodes: Long 10, Goal 20 per evaluation, as expected). Correction: the earlier count of "1,533,326 router calls" in the Experiment 1 entry includes these non-rollout calls. v4 clears the context after each action so only rollouts are logged in future runs.
  - **Part A, routing drift (Long).** The router did not forget task index 1. After task 9 its frames are still routed to expert 1 with weight about 1.98 (top-1 share 1.0 in the img and fusion groups), newer experts get about 0.02, and the cosine of the mean routing vector to its baseline stays 0.999 (every task stays in 0.994-1.000; split-half noise floor 5th percentile 0.994). Across the 45 (K, J) cells, Spearman(routing drift, success drop) = -0.14, p = 0.36. The cosine is a coarse measure, but the expert shares and weights above agree with it. Conclusion: coefficient replay held the routing; the 1.0 -> 0.1 drop of task 1 is not router drift.
  - **Likely cause: the "frozen" experts decay under AdamW weight decay (found in the checkpoints, no GPU).** Every old expert's weights shrink uniformly after it is created: expert 1's norm falls 9.66 -> 7.74 (relative change 0.1984 in A, B and bias alike, i.e. a pure scale factor 0.80); expert 0 falls to 0.79 of its original norm by task 9, expert 2 to 0.83, expert 5 to 0.89. The optimizer is `AdamW(self.policy.parameters(), lr=1e-4, weight_decay=0.1)` (train/optimizer/adam_w.yaml, algos/dmpel.py L239) and an expert is "frozen" only by `torch.where(frozen_mask, w.detach(), w)` on its rows of a stacked pool tensor, so its gradient is zero rather than absent and the decoupled decay still applies. LoRA output scales with the product of A and B, so a 0.8 factor on both is about 0.64 on the expert's contribution. The Goal run shows the same effect, smaller: expert 0 at 0.894 of its norm after 9 more tasks, because a Goal task has about half the optimizer steps (about 200 vs 430 batches per epoch). The size is of the order of lr x wd = 1e-5 per step but smaller than a per-step estimate for Long (about 4.5% per task predicted, 2-3% observed); the gap is not explained. Not yet shown causally: task index 0 also decayed (expert 0 at 0.79) yet stayed at 0.7, so sensitivity differs by task. Proposed test (GPU, about 20 min, needs approval): evaluate the final model with each expert's weights restored from its own creation checkpoint, and see whether task 1 recovers.
  - **Part B, mid-episode routing (just-learned evaluations, tasks 1-9; Long 90 episodes, Goal 180).** Expert-switch rate (any group, per step) Long 0.032 vs Goal 0.039, ratio 0.83x (95% CI 0.73-0.94); first 200 steps 0.89x (0.79-1.01). The router mostly keeps the current task expert in img/extra/tem and alternates experts 0/1 in txt/head. By the plan's own decision rule (ratio < 1.2) the router does not switch more on Long than on Goal and does not switch at gripper phase boundaries: no mechanistic basis for phase-level routing from this data.
